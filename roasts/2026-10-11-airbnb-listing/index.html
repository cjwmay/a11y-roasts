Airbnb 房源页：80 个没有名字的照片按钮

Airbnb Listing Page: 80 Photo Buttons With No Names

审的是我自己的房源页（SoFi USC West LA Retreat）—— 每个问题都可亲自验证。方法：真机键盘走查 + DevTools Accessibility tree 取证。Airbnb 有大量 A/B 测试，以下为 2026-10-11 抓到的版本。

I audited my own listing page (SoFi USC West LA Retreat) — every issue below is verifiable first-hand. Method: real-browser keyboard walkthrough + DevTools Accessibility tree forensics. Airbnb runs heavy A/B tests; this reflects the version captured on 2026-10-11.

①Photo Tour 里约 80 个照片按钮没有 accessible name~80 photo buttons in Photo Tour have no accessible nameHigh

现象

点"Show all photos"进入 Photo Tour 弹窗，照片按房间分区陈列。Accessibility tree 里这些照片按钮全是裸 button。查 HTML 实锤：<button aria-label=""> 包着 <img aria-hidden="true" alt=""> —— 按钮名和图片 alt 双双为空。

用户影响

读屏用户面对几十个无法区分的"button"，照片浏览基本不可用 —— 而照片恰恰是房源页最核心的信息载体。

WCAG 依据

4.1.2 Name, Role, Value（控件必须有可被读出的名字）；连带 1.1.1 Non-text Content。

修复方案

不需要手写 80 条文案 —— 数据源现成：同一页照片网格的第 1、2 张已有高质量描述（"Resort style backyard"），说明照片元数据里有描述字段，只是 Photo Tour 按钮没接进来。模板：aria-label="{房间名} photo {n} of {m}: {照片描述}"；去掉按钮上 aria-label="" 的空值覆盖；img 保持 alt="" aria-hidden="true"（避免读两遍）。

What

Opening "Show all photos" launches the Photo Tour dialog with photos grouped by room. In the accessibility tree, every photo button is a bare button with no name. The HTML confirms it: <button aria-label=""> wrapping <img aria-hidden="true" alt=""> — both the button name and the image alt are empty.

Impact

Screen reader users face dozens of indistinguishable "buttons" — photo browsing is effectively broken, and photos are the single most important content on a listing page.

WCAG

4.1.2 Name, Role, Value; also 1.1.1 Non-text Content.

Fix

No need to hand-write 80 labels — the data already exists: photos 1–2 in the same page's grid have rich descriptions ("Resort style backyard"), so photo metadata carries descriptions; the Photo Tour buttons just aren't wired to it. Template: aria-label="{Room} photo {n} of {m}: {description}"; drop the empty aria-label="" override; keep img as alt="" aria-hidden="true" to avoid double announcement.

②Guests 人数选择器 Esc 关不掉Guests stepper can't be dismissed with EscapeMedium

现象

预订面板的 GUESTS 按钮，键盘 Enter 能打开人数选择器，展开/收起状态也正确暴露，但连按多次 Esc 选择器依然开着，只能一路 Tab 到"Close"按钮去关。

用户影响

纯键盘用户被迫多走一串 Tab 才能脱身；Esc 关弹窗是全网通用约定，违背它等于在用户肌肉记忆上埋雷。

WCAG 依据

2.1.1 Keyboard；行为对照 APG 的 disclosure / dialog 模式 —— Esc 关闭是预期行为。

修复方案

打开时监听 keydown，Esc → 关闭 popover；关闭后把焦点还给触发它的 GUESTS 按钮（focus management）。5 行代码级修复，建议进组件库的 popover 基类，一次修好全站同类控件。

What

The GUESTS button in the booking panel opens the guest stepper via keyboard (Enter), and expanded/collapsed state is correctly exposed — but pressing Escape repeatedly leaves the stepper open. The only keyboard way out is tabbing all the way to the "Close" button.

Impact

Keyboard-only users are forced through a long Tab detour to escape; Escape-to-dismiss is a universal convention, and violating it plants a mine in users' muscle memory.

WCAG

2.1.1 Keyboard; behaviorally, the APG disclosure/dialog pattern expects Escape to dismiss.

Fix

Listen for keydown while open: Escape closes the popover and returns focus to the GUESTS trigger (focus management). A ~5-line fix — land it in the shared popover base class and every similar control site-wide is fixed at once.

③Guests 按钮的 accessible name 是 "1guest"Guests button's accessible name is "1guest"Low

现象

按钮的计算名是 "1guest" —— 中间没空格；页面可见文案是 "GUESTS" / "1 guest"，accessible name 和任一可见字符串都不一致。

用户影响

Voice Control 用户说"click 1 guest"时，系统按名字匹配控件，"1guest"对不上，可能点不中 —— 纯视觉用户永远感知不到的一类 bug。

WCAG 依据

2.5.3 Label in Name（可见标签的文字必须出现在 accessible name 里）。

修复方案

根因大概率是 i18n 模板 {count}{unit} 拼字符串漏了空格。改成 "{count} {unit}"（或别手写覆盖，让名字从可见文本计算）。顺带全站扫一遍同类拼接：金额、日期、人数这种"数字+单位"模板是重灾区。

What

The button's computed accessible name is "1guest" — no space. The visible text reads "GUESTS" / "1 guest", so the accessible name matches neither visible string.

Impact

Voice Control users saying "click 1 guest" match controls by name — "1guest" won't match, and the tap can miss. A class of bug sighted users never perceive.

WCAG

2.5.3 Label in Name (visible label text must appear in the accessible name).

Fix

Root cause is almost certainly an i18n template concatenating {count}{unit} without a space. Change to "{count} {unit}" (or stop overriding and let the name compute from visible text). Sweep the codebase for the same pattern — "{number}{unit}" templates for prices, dates, and counts are repeat offenders.
